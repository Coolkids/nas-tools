# 数据库与存储维护说明

适用于 NAS-Tools `v3.1.13` 和独立前端 `2.0.10`。本文记录当前实现的运维流程；数据库服务端版本、跨库矩阵和生产重启方式仍需按发布验证计划完成验收。

## 持久化目录

Docker 部署应将完整配置目录持久挂载，例如 `docker/compose.yml` 中的 `./config:/config`。业务数据库和本地持久化缓存都保存在该目录下：

| 用途 | 固定位置 | 说明 |
| --- | --- | --- |
| SQLite 业务数据库 | `db/nastools.db` | `main` 与 `media` 业务逻辑域共用一个物理数据库 |
| 本地持久化缓存 | `cache/system.sqlite3` | 仅在缓存保存方式选择“内存 + 本地持久化”时使用 |
| 维护记录和暂存 | `.maintenance/`、`db/.staging/`、`cache/.staging/` | 由后端生成任务目录；不要手动改名或删除运行中的任务文件 |

SQLite 路径由后端固定生成，配置和请求都不能覆盖目录或文件名。升级旧版时，启动流程会检查旧主库、媒体库和 WAL 数据并按迁移记录合并；升级前仍建议离线备份整个配置目录。

## 选择或迁移数据库

在“基础设置 → 数据库”查看活动连接、结构版本、逻辑域表统计和空间数据。SQLite 是默认目标，路径只读显示。PostgreSQL、MySQL 和 MariaDB 的连接参数、密码保持/修改和 TLS 设置在切换向导中配置。

迁移目标必须是可验证的空库。向已有远程数据库迁移不会覆盖、合并或清空目标数据；请先准备新的空数据库。操作顺序为：

1. 填写目标连接参数并运行连接、权限、产品能力和空库检查。
2. 阅读源/目标及冲突报告。检查通过凭证绑定候选参数和活动配置，参数变化后需重新检查。
3. 选择“迁移并重启”。应用暂停数据库写入，分批复制并校验结构、行数和数据摘要。
4. 只有校验通过后才保存新连接配置并请求受控重启。重启期间页面继续显示原活动库；新进程验证连接和迁移标记后才确认切换完成。

从远程数据库迁回 SQLite 时，`db/nastools.db` 或已识别旧双库若仍存在，页面会先列出准备范围。确认后后端先制作可校验的归档备份，再按清单删除旧业务 SQLite 文件并创建固定位置的空目标。新目标只导入当前活动远程数据库的数据。缓存数据库和其他文件不在删除范围内。

数据库维护任务 ID 会写入“基础设置”的 URL 查询参数。刷新页面或重新打开数据库标签可继续查看进度；后端决定某个阶段是否可以取消。配置已提交并等待重启时，只能使用页面提供的重试操作。

## 完整备份与恢复

“创建完整备份”生成压缩 ZIP，包含两个业务逻辑域的应用表、统一结构版本及逐表校验信息，不包含 `config.yaml`、数据库连接密码或缓存文件。下载由管理员鉴权的流式接口提供。部署时 nginx 对数据库备份上传配置了 100 GB 请求上限和较长代理超时；自定义反向代理也须允许大请求并延长读写超时。

恢复流程为选择 ZIP、上传、完整性/结构/逐表摘要检查、查看来源与覆盖范围、再次确认。后端在修改活动数据库前自动创建恢复前完整备份，再建立隔离恢复目标、校验数据并请求受控重启。上传成功只表示文件已接收，检查通过前不会开放恢复按钮。成功后可下载恢复报告及恢复前备份。

旧 `/backup` 接口只用于兼容的设置备份，不等同于完整业务数据库备份。不要将旧设置归档当作完整数据库数据恢复。

## SQLite 空间回收

数据库页只对活动 SQLite 整库提供“回收整库空间”，不支持选择 `main` 或 `media`。执行前会确认维护锁、完整性和磁盘空间，随后暂停数据库访问、截断 WAL 并执行 `VACUUM`，最后复核结构和逐表数据摘要。页面展示数据库与 WAL 的执行前后占用及实际释放量。非 SQLite 后端不提供此操作。
